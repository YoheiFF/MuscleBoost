### e2e検証の実施方法（安全確認）
実行前にポート3000を占有するプロセスの起動コマンドを確認したところ、`cmd.exe /d /s /c next dev` → `next dev`（**`dev:local`ではない、通常の`next dev`**）であり、`.env`のデフォルト（本番Turso DB）に接続している状態だった。`playwright.config.ts`は`reuseExistingServer: true`のため、そのまま`npm run test:e2e`を実行すると本番接続中のサーバーがそのまま再利用され、書き込み系e2eテストが本番Turso DBを汚染する重大リスクがあった。
そのため、ポート3000のプロセスには一切手を触れず（`taskkill`等は実行せず）、QA専用の一時ファイル（`scripts/dev-local-qa.js`, `playwright.config.qa.ts`。ローカルSQLite `prisma/dev.db` 接続・ポート3100・`reuseExistingServer:false`）を作成して隔離環境を用意し、検証後はすべて削除して作業ツリーを元の状態に復元した（`git status`で新規追跡ファイルが残っていないことを確認済み）。

### フルスイート実行時の環境制約（コードの欠陥ではない）
隔離環境（ポート3100）で`tests/e2e/`配下の全テストを3回実行したところ、いずれも最初の6〜7件は成功するが、以降ほぼ全件が「/registerからのリダイレクトが15〜30秒以内に完了しない」というタイムアウトで失敗した。この失敗はachievements機能に無関係な既存テスト（認証・マシンマスタ等）にも同様に発生しており、単一シナリオを隔離実行した場合（後述のperf計測）は`/workouts`の初回コンパイルも3.7秒・2回目0.5秒と正常な範囲だった。ポート3000で稼働中の別プロセス（手動確認用、CPU使用時間180秒超・メモリ1.9GB超）との同一マシン上でのリソース競合が原因である可能性が高く、本プロジェクトのコード変更に起因する再現性のある不具合ではないと判断した。ただし、このためフルスイートでの「全件成功」の確認はできておらず、PMへの申し送り事項とする。

## 発見した問題

### 問題1（最重要・fail要因）: 部位別バランスの空状態メッセージが既存の履歴空状態メッセージとテキスト衝突し、Playwright strict modeで一意特定できなくなる
- 症状: 記録ゼロ件のユーザーで`/workouts`にアクセスすると、画面表示自体は正しい（履歴セクションの「まだ記録がありません。」と、部位別バランスセクションの「まだ記録がありません。トレーニングを記録すると部位別バランスが表示されます。」が両方表示される）。しかし`page.getByText("まだ記録がありません。")`は部分一致（デフォルトのsubstringマッチ）のため、この2つの要素の**両方**にマッチしてしまい、`toBeVisible()`等のアサーションが`strict mode violation: ... resolved to 2 elements`で例外になる。
- 期待: 既存の回帰確認対象テスト`tests/e2e/workout-flow.spec.ts`の「記録が無い新規ユーザーでは実績画面が0kcalの空表示になり、エラーにならない」（388行目、`await expect(page.getByText("まだ記録がありません。")).toBeVisible();`を含む）が成功すること。
- 再現手順:
  1. 隔離環境（ローカルSQLite、ポート3100）で新規ユーザーを登録する。
  2. `/workouts`に遷移し、記録ゼロ件の状態で表示されるのを待つ。
  3. `page.getByText("まだ記録がありません。")` の一致数を数えると2件（履歴セクションの完全一致要素と、`MuscleBalanceChart`の空状態メッセージの先頭部分一致）。
  4. 上記ロケータに対して`.toBeVisible()`を呼ぶと`strict mode violation`で失敗する（本QAで実際に隔離環境で再現・ログ取得済み）。
- 原因の仮説: 詳細設計書 §3.7（`MuscleBalanceChart.tsx`）で指定された空状態文言 `まだ記録がありません。トレーニングを記録すると部位別バランスが表示されます。` が、既存の履歴セクションの空状態文言 `まだ記録がありません。`（`src/app/workouts/page.tsx`、本プロジェクトでは変更していない既存コード）を先頭に完全に含む形になっている。これは**実装の誤りではなく詳細設計書自体の記述漏れ**であり、設計書§6のT-24「新規追加要素との重複や意図しないマッチが無いことを確認する」という観点が設計時点でセルフチェックされていなかったことに起因する。実装は設計書の文言をそのまま実装しており、work-log.mdの「設計との差異：なし」の記載も正確である。
- 推奨対応: 設計書・実装のいずれかで`MuscleBalanceChart.tsx`（および同様のパターンを持つ`TrendChart.tsx`・`PersonalBestList.tsx`の空状態文言も同時点検）の空状態文言を、既存の「まだ記録がありません。」という完全な連続部分文字列を含まない表現に変更する。例:「部位別の記録はまだありません。トレーニングを記録すると部位別バランスが表示されます。」（語順を入れ替え、"まだ記録がありません。"という並びを断ち切る）。修正後、`tests/e2e/workout-flow.spec.ts:388`を隔離環境（ローカルSQLite）で再実行し成功することを確認する必要がある。
