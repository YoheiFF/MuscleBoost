# 要件定義書: ジムトレーニング消費カロリー管理システム（MuscleBoost）

## 0. 参照
- 情報収集レポート: `C:\project\MuscleBoost\.project\research\topics\2026-09-12-1539-gym-tracker.md`
- 本書は Why → What → How の順で記述する。How の詳細（画面遷移・型・関数）は `basic-design.md` / `detailed-design.md` に譯る。

---

## 1. Why（背景・目的）

- ユーザーはジムに通い始めたばかりで、マシン別のトレーニング内容（セット数・レップ数・時間）を記録し、**そのトレーニングでどれくらいカロリーを消費したか**を自動算出して可視化したい。
- 手書き・Excel管理では「今日はどのマシンを何セットやったか」と「消費カロリーの目安」を同時に管理しづらく、継続のモチベーションが続かない。
- 家族・友人など複数人での利用も想定されるため、各自のログイン・データ分離が必須。
- カロリー算出は医学的に厳密な値ではなく「目安」であることを前提に、それでも継続記録の励みになる程度の妥当な近似値を、透明な根拠（MET値の出典）とともに提供する。

## 2. What（ユーザー要件）

### 2.1 ペルソナ
- 主ユーザー: ジム初心者〜中級者。週2〜4回程度通う想定。スマホ・PC両方からアクセス。
- 複数人（家族・友人）が同一システムに各自のアカウントで登録し、それぞれ自分の記録のみを見る。

### 2.2 ユーザーストーリー
1. ユーザーとして、メールアドレスとパスワードでアカウント登録・ログインしたい。他人の記録は見えないようにしたい。
2. ユーザーとして、プロフィールに自分の体重（デフォルト値）を設定したい。体重は変動するので、必要なら記録都度上書きしたい。
3. ユーザーとして、ジムのマシン一覧（レッグプレス、チェストプレス、トレッドミル等）から選んでトレーニング記録をつけたい。
4. ユーザーとして、1回のジム訪問（セッション）の中で複数のマシンを記録したい（例: 今日はチェストプレス3セット→レッグプレス3セット→トレッドミル20分）。
5. ユーザーとして、各マシンについてセット数・レップ数・運動時間を入力すると、消費カロリーが自動計算されて表示されてほしい。
6. ユーザーとして、自分がよく使うマシンがマスタに無い場合、自分用にマシンを追加登録したい（MET値は目安として自分で入力する）。
7. ユーザーとして、過去の記録一覧・週間/月間の消費カロリー合計をダッシュボードで見たい。
8. ユーザーとして、カロリー値が「MET値ベースの目安」であることを画面上で理解できるようにしてほしい（過度な精度を期待しないため）。

### 2.3 対象外（今回のスコープ外）
- ウェアラブル端末・心拍センサー連携による実測カロリー取得。
- 栄養・食事管理機能。
- トレーナー・管理者による他ユーザー管理画面（初期リリースでは無し。マシンマスタの追加はシード投入のみで対応し、UI上の「管理者専用マスタ編集画面」は作らない）。
- SNS共有・ランキング機能。
- モバイルネイティブアプリ化（将来検討、BrainGameのCapacitor実績を参考にできるが本プロジェクトのスコープには含めない）。

## 3. システム要件（機能要件）

### 3.1 認証・ユーザー管理
- FR-01: メールアドレス + パスワードでのユーザー登録ができる。
- FR-02: メールアドレス + パスワードでログイン・ログアウトができる。
- FR-03: ログインしていないユーザーは記録系ページ（ダッシュボード、記録、プロフィール等）にアクセスできず、ログインページへリダイレクトされる。
- FR-04: ユーザーは自分のデータ（トレーニング記録・体重履歴・カスタムマシン）のみ参照・編集・削除できる。他ユーザーのデータには一切アクセスできない（アクセス制御必須）。

### 3.2 プロフィール
- FR-05: ユーザーは表示名・デフォルト体重(kg)を設定・更新できる。
- FR-06: ユーザーは体重の履歴（日付＋体重）を記録できる。デフォルト体重は「現在の基準値」として使い、体重履歴とは別に保持する。

### 3.3 マシン（エクササイズ）マスタ
- FR-07: システムは初期状態で、有酸素マシン・筋トレマシンを含む代表的なマシンのマスタデータ（名称・部位・強度カテゴリ・MET値・根拠メモ）をあらかじめ保持する（シードデータ）。
- FR-08: ユーザーはマスタに無いマシンを「自分用カスタムマシン」として追加できる（名称・部位・強度カテゴリ・MET値を自分で入力）。
- FR-09: カスタムマシンは作成した本人のみ編集・削除できる。シードによる共通マスタはユーザーが編集・削除できない（データ整合性の保護）。
- FR-10: マシン一覧は部位・強度カテゴリで絞り込み表示できる。

### 3.4 トレーニング記録
- FR-11: ユーザーは「ワークアウトセッション」（1回のジム訪問、日付＋任意メモ）を作成できる。
- FR-12: 1つのセッションに複数の「トレーニングログ」（マシン単位の記録: セット数・レップ数・運動時間(分)・任意で体重上書き）を追加できる。
- FR-13: トレーニングログ保存時に、下記の式で消費カロリーを自動計算し、記録として保存する。
  - `kcal = MET値 × 体重(kg) × 運動時間(h) × 1.05`
  - MET値はそのマシンのマスタ値（記録時点のスナップショットを保存し、後でマスタのMET値が変更されても過去記録の値は変わらない）。
  - 体重(kg)は「そのログの上書き入力」＞「プロフィールのデフォルト体重」の優先順で決定する。両方無い場合はエラーとし、体重入力を促す。
  - 運動時間(h) はユーザーが入力した運動時間(分)を60で割った値。
- FR-14: セット数・レップ数はカロリー計算式には直接使用しないが、記録・表示用の情報として保持する（研究レポートの申し送り事項どおり）。
- FR-15: （任意機能・必須ではない）セット数 × 1セットあたりの想定秒数から運動時間を自動算出する入力補助を提供してもよい。ユーザーが手入力した運動時間があればそちらを優先する。
- FR-16: ユーザーはトレーニングログ・セッションを編集・削除できる（削除時はカロリーも含めて再計算・削除される）。

### 3.5 ダッシュボード・履歴
- FR-17: ユーザーは自分の過去のワークアウトセッション一覧（日付・マシン数・合計消費カロリー）を見られる。
- FR-18: ユーザーはセッション詳細（各マシンのセット数・レップ数・時間・消費カロリー）を見られる。
- FR-19: ダッシュボードでは直近1週間・直近1ヶ月の合計消費カロリー・記録回数などの集計を表示する。
- FR-20: カロリー表示のある画面には「MET値に基づく目安であり、個人差があります」という注記を表示する。

## 4. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-01 | セキュリティ | パスワードは平文で保存しない（ハッシュ化必須）。セッションはHTTP Only Cookie（JWT）で管理する。 |
| NFR-02 | セキュリティ | 全てのデータアクセス（Server Action / API）でログインユーザーIDによる所有権チェックを行う。 |
| NFR-03 | 可搬性 | 開発環境はSQLite、将来的にPostgreSQLへ無停止で移行できるようPrismaスキーマをRDBMS非依存に保つ（DB固有機能・enum型に依存しない）。 |
| NFR-04 | 保守性 | MET値はマスタデータとして分離し、コード変更なしに値の追加・調整ができる（シードスクリプト経由）。 |
| NFR-05 | ユーザビリティ | スマートフォン（幅375px程度）でも記録入力が問題なく行える レスポンシブUI。 |
| NFR-06 | 透明性 | カロリー値が推定値であることをUIで明示する（免責文言）。 |
| NFR-07 | 可用性 | 個人〜小規模利用を想定。特別な高可用性要件は無し（単一VPS/単一インスタンスで十分）。 |
| NFR-08 | 国際化 | 初期リリースは日本語UIのみで良い（多言語対応は将来検討）。 |
| NFR-09 | テスト容易性 | カロリー計算ロジックは純粋関数として分離し、単体テスト可能にする。 |

## 5. 重要な設計判断（要件確定事項）

研究レポートで「未確定」とされていた点を、本要件定義で以下のように確定する。

1. **1.05補正係数の採用**: 採用する。厚生労働省「健康づくりのための身体活動基準」に基づく国内標準の計算式 `MET × 体重 × 時間 × 1.05` を採用する。将来変更したい場合に備え、係数は `CALORIE_CORRECTION_FACTOR` という単一の定数として実装し、コード1箇所の変更で無効化・変更可能にする。
2. **マシン別MET値が公的に存在しない問題**: マシン（エクササイズ）マスタは「マシン名」「部位」「強度カテゴリ（軽度/中等度/高強度など）」「MET値」「根拠メモ」を持つ。同一マシンでも強度によって消費が変わることを表現するため、シードデータでは主要な筋トレマシンについて軽度/中等度/高強度の3種のレコードを用意する（例:「チェストプレス（軽度）」「チェストプレス（中等度）」「チェストプレス（高強度）」）。ユーザーは自分の負荷感に近いものを選ぶ。有酸素マシンは速度・ワット数帯ごとに個別レコードとする（厚労省メッツ表に準拠）。
3. **セット数・レップ数とMET計算の関係**: カロリー計算には使用しない。記録・表示専用の付随情報とする。UIで「セット数を増やしても運動時間が変わらなければカロリーは変わりません」という趣旨が伝わるよう、運動時間の入力を主役として配置する。
4. **体重の入力タイミング**: プロフィールにデフォルト体重を保持し、各トレーニングログでも個別に上書き入力できる、両対応のデータモデルとする。
5. **技術スタック**: Next.js (App Router) + TypeScript + Prisma + SQLite(開発)/PostgreSQL対応 + Auth.js(NextAuth) を採用する（詳細は `basic-design.md` を参照）。

## 6. 受け入れ条件（Acceptance Criteria）

- AC-01: 新規ユーザーがメール・パスワードで登録し、ログインできる。
- AC-02: ログインしていない状態でダッシュボード等にアクセスすると `/login` にリダイレクトされる。
- AC-03: ユーザーAがユーザーBのワークアウトセッション・ログ・カスタムマシンを一覧・詳細・編集・削除のいずれの手段でも参照・操作できない（直接ID指定アクセスを含む）。
- AC-04: プロフィールでデフォルト体重を70kgに設定し、MET値3.0・運動時間30分のトレーニングログを体重上書き無しで保存すると、消費カロリーが `3.0 × 70 × 0.5 × 1.05 = 110.25` （四捨五入等の丸め規則は detailed-design で規定）として保存・表示される。
- AC-05: トレーニングログ作成時に体重上書きも無く、プロフィールのデフォルト体重も未設定の場合、保存が拒否され「体重を入力してください」旨のエラーが表示される。
- AC-06: マスタ由来のマシン（isCustom=false）はユーザー操作で編集・削除できない。カスタムマシン（isCustom=true）は作成者のみ編集・削除できる。
- AC-07: セット数・レップ数を変更しても運動時間が同じであれば、算出される消費カロリーは変化しない。
- AC-08: ダッシュボードに直近7日間・直近30日間の合計消費カロリーが表示される。
- AC-09: カロリーが表示される全ての画面に「目安値である」旨の注記が表示される。
- AC-10: マスタのMET値を後から変更しても、既存のトレーニングログの消費カロリー表示は変わらない（記録時点のMET値スナップショットを使用）。
