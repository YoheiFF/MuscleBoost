# 最終報告 - 2026-09-12-1539-gym-tracker

## 依頼
ジムに通い始めたユーザーが、マシン種類・セット数・レップ数・運動時間から消費カロリーを自動計算し、
複数人でログインして各自のトレーニング記録を管理できる Web アプリを構築する。

## 情報収集（Phase 1）
- マシン別の公的な MET 値は存在しない（MHLWの運動のメッツ表・米国Compendium of Physical Activitiesともに、機種名ではなく運動の強度・種別単位）。
  → マシンマスタに「強度カテゴリ（軽度/中等度/高強度）」を持たせる設計方針を確定。
- MET値は個人差・セット間の休憩を反映しない静的な目安値であるという限界を設計・QAへ申し送り。
- 環境内の既存プロジェクト（BrainGame, civilserviceapp）の傾向から Next.js + TypeScript + Tailwind 系スタックを採用候補とした。
- 詳細: `.project/research/topics/2026-09-12-1539-gym-tracker.md`

## 設計（Phase 2）
- 技術スタック: Next.js 15 (App Router) + TypeScript + Prisma(SQLite、PostgreSQL対応可) + Auth.js v5 (Credentials/JWT) + bcryptjs + Zod + Tailwind v4
- カロリー計算式: `kcal = MET × 体重(kg) × 時間(h) × 1.05`（`CALORIE_CORRECTION_FACTOR` として1箇所に集約）
- データモデル: User / Exercise（マシンマスタ、強度カテゴリ・MET値保持） / WorkoutSession / WorkoutLog（セット数・レップ数・時間・カロリーのスナップショット） / WeightLog
- マスタのMET値変更が過去記録に影響しないよう、記録時点でスナップショット保存する設計
- 全Server Actionでユーザー所有権チェックを必須化し、マルチユーザーのデータ分離を保証
- 影響範囲・詳細設計書: `.project/design/2026-09-12-1539-gym-tracker/detailed-design.md`（要件定義書・基本設計書も同ディレクトリ）
